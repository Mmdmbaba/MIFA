این پروژه را می‌شود صفر تومان بالا آورد

تحقیق جامع درباره میزبانی رایگان اپ شخصی MIFA روی Vercel، Cloudflare و پلتفرم‌های مشابه — با پاسخ به سه سؤال: چند پروژه می‌شود بالا آورد؟ چه سقف‌هایی دارد؟ و آیا می‌شود با API کاری کرد که دیپلوی خودش انجام شود؟

✓

پاسخ کوتاه: بله — و حتی بهتر از چیزی که فکر می‌کردی

برای اپ شخصی تک‌کاربره‌ای مثل MIFA، سقف‌های رایگان این پلتفرم‌ها آن‌قدر بالاست که مصرف واقعی تو زیر ۱٪ آن‌ها می‌شود. مشکل «رول‌بک شدن سندباکس» هم با یک ترکیب ساده حل می‌شود: کد در GitHub بماند + دیپلوی خودکار با API — این‌طوری حتی اگر همه‌چیز پاک شود، چند دقیقه‌ای برمی‌گردد و دیتای تو هم روی دیتابیس ابری رایگان امن است.
برنده تحقیق: Cloudflare Pages + Workers + دیتابیس D1 (همه‌چیز رایگان، بدون خواب‌ رفتن سرویس) و جایگزین عالی: Vercel Hobby (سازگارترین با Next.js، فقط برای استفاده شخصی — که دقیقاً شرایط توست).

Netlify

قبلاً خوب بود — از سپتامبر ۲۰۲۵ سقوط کرد

Netlify قیمت‌گذاری را به سیستم «اعتباری» تغییر داد: پلن رایگان فقط ۳۰۰ اعتبار در ماه می‌دهد و باندویث هر گیگابایت ۲۰ اعتبار حساب می‌شود؛ یعنی عملاً ~۱۵ گیگابایت ترافیک در ماه. اعتبارها که تمام شوند، پروژه‌ها تا ماه بعد متوقف می‌شوند.

دیتابیس‌های رایگان — جایی که داده‌های تو می‌ماند

میزبانی که پاک شود مهم نیست؛ مهم این است که داده‌ات جاودانه باشد. این‌ها سقف‌های واقعی پلن‌های رایگان دیتابیسی است:

دیتابیس نوع سقف رایگان می‌خوابد؟ API مدیریت حکم برای MIFA
Cloudflare D1 SQLite سرورلس ۵۰۰MB هر دیتابیس، ۵GB کل اکانت، ۵ میلیون ردیف‌خوانی و ۱۰۰ هزار ردیف‌نویسی در روز هرگز ❌ REST API + Wrangler 🏆 بهترین — هم‌خانواده Worker
Neon PostgreSQL سرورلس ۱۰۰ پروژه، هر کدام ۱ گیگ استوریج + ~۱۰۰ ساعت محاسبه خیر — فقط cold start کوتاه دارد ✔ عالی برای جفت‌شدن با Vercel
Supabase PostgreSQL + Auth + Storage ۲ پروژه فعال، ۵۰۰MB دیتابیس، ۵ گیگ خروجی، ۵۰ هزار کاربر auth ⚠ بعد از ۷ روز بی‌فعالیتی Management API کامل (با MCP) خوب ولی باید هفته‌ای یک بار سر بزنی
Turso SQLite توزیع‌شده ۵۰۰ دیتابیس رایگان خیر دارد جذاب — به‌تازگی توسط Supabase خریداری شد (اکتبر ۲۰۲۶)
MongoDB Atlas (M0) NoSQL سندگرا ۵۱۲ مگابایت، بدون نیاز به کارت خیر دارد گزینه پشتیبان
Upstash Redis Redis سرورلس ~۲۵۶ مگابایت، ~۱۰ هزار دستور در روز خیر دارد برای کش/نشست — نه دیتای اصلی
⚠ بزرگ‌ترین تله تحقیق: Supabase پروژه‌های رایگان را بعد از ۷ روز بی‌فعالیتی به‌خواب می‌برد — یعنی اپ تو فردا صبح ممکن است باز نشود مگر اینکه هر هفته یک بار بازش کنی. Neon و D1 این مشکل را ندارند؛ برای اپ مالی که باید «همیشه بی‌درنگ» باشد، همین یک قلم تعیین‌کننده است.

MIFA واقعاً چقدر از این سقف‌ها را مصرف می‌کند؟

برآورد مصرف یک کاربر واقعی (تو!) در برابر سقف پلن رایگان Cloudflare/Vercel — فاصله‌ها خیره‌کننده است:

درخواست‌های ماهانه — حدود ۳ هزار از ۱ میلیون (Vercel) / ۳ میلیون (Workers)≈ ۰.۳٪
باندویث ماهانه — حدود ۱۰۰ مگابایت از ۱۰۰ گیگابایت≈ ۰.۱٪
حجم دیتابیس — چند مگابایت تراکنش از ۵۰۰ مگابایت (D1)≈ ۲٪
دیپلوی ماهانه — حدود ۲۰ تا از ۱۰۰ دیپلوی در روز (Vercel)≈ ۰.۷٪ روزانه
نتیجه: حتی اگر ده اپ شخصی دیگر هم کنار MIFA بالا بیاوری، به هیچ سقفی نزدیک نمی‌شوی. پاسخ سؤال «چند پروژه می‌شود بالا آورد؟»: در Cloudflare ۱۰۰ پروژه، در Vercel ۲۰۰ پروژه، در Neon ۱۰۰ دیتابیس و در Turso ۵۰۰ دیتابیس — همگی رایگان.

نقشه راه استقرار — ۵ قدم تا آنلاین شدن

با مسیر پیشنهادی اول (Cloudflare)؛ برای Vercel هم دقیقاً همین قدم‌ها با نام‌های مشابه صدق می‌کند:

کد را به GitHub ببر

یک ریپو (خصوصی یا عمومی — برای Actions عمومی رایگان‌تر است) بساز و کد MIFA را push کن. از این لحظه کد تو مصون از رول‌بک است: git push origin main

دیتابیس رایگان بساز

در Cloudflare از بخش Storage یک D1 بساز؛ مایگریشن جداول (تراکنش‌ها، دوره‌های پرداخت، تنظیمات آنبوردینگ) را اجرا کن: wrangler d1 execute mifa-db --file=schema.sql

اتصال ریپو به Pages

در داشبورد Cloudflare Pages ریپو را وصل کن؛ از این به بعد هر push یعنی بیلد و انتشار خودکار با دامنه رایگان mifa.pages.dev — یا با یک فرمان مستقیم: wrangler pages deploy dist

کلیدها را در Environment Variables بگذار

آدرس دیتابیس و توکن‌ها هرگز داخل کد نوشته نمی‌شوند؛ در تنظیمات پروژه ذخیره‌شان کن تا با هر دیپلوی خودکار تزریق شوند.

دوربین بک‌آپ بگذار

در خود MIFA دکمه «خروجی CSV/JSON» داشته باش (قرار بود در اپ باشد) + ماهی یک بار از D1 dump بگیر: wrangler d1 export mifa-db --output=backup.sql

۹

ریسک‌ها و نکاتی که باید بدانی

⚠ تله‌هایی که دیگران گرفتارشان شده‌اند

  • ▪ خواب‌رفتن Supabase بعد از ۷ روز بی‌فعالیتی — اگر انتخابش کردی، یک کرون‌جاب یا بازدید هفتگی لازم است.
  • ▪ حذف دیتابیس Render بعد از ۳۰ روز — هیچ‌وقت دیتای اصلی را آن نگذار.
  • ▪ سیستم اعتباری Netlify — پروژه وسط ماه متوقف می‌شود اگر ۱۵ گیگ رد شود.
  • ▪ سقف CPU تابع Workers (۱۰ms) — محاسبات سنگین را در کلاینت یا با D1 انجام بده، که برای MIFA طبیعتاً همین‌طور است.

🛡 چند نکته صادقانه

  • ▪ Vercel فقط شخصی است — MIFA مصرف شخصی توست پس مجاز؛ فقط روزی تجاری‌اش نکن.
  • ▪ دسترسی از ایران — برخی سرویس‌ها محدودیت منطقه‌ای دارند؛ تجربه معمول این است که GitHub و Cloudflare در دسترس‌ترند و دامنه‌های رایگان (pages.dev / workers.dev / vercel.app) بدون هزینه کار می‌کنند. قبل از مهاجرت کامل، یک تست ساده از شبکه خودت انجام بده.
  • ▪ مالکیت داده — با قابلیت خروجی CSV در خود اپ، داده‌ات همیشه قابل حمل است و به هیچ پلتفرمی گروگان نمی‌شود.
  • ▪ این سقف‌ها هر از گاهی تغییر می‌کنند — لینک منابع رسمی پایین گزارش را نگه دار.
